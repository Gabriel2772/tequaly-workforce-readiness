# TWR Copilot and MCP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expor os Application Services por um copiloto OpenAI-compatible e pelo Claude/MCP sem duplicar lógica, SQL ou políticas de autorização.

**Architecture:** Um `ToolRegistry` único descreve e executa ferramentas sobre Application Services. `AIOrchestrator` adapta esse catálogo ao `LLMProvider`; o servidor MCP adapta o mesmo catálogo ao SDK MCP oficial. Escritas usam intents pendentes e confirmação humana antes da persistência.

**Tech Stack:** OpenAI Python SDK, FastAPI, Pydantic 2, SDK MCP Python oficial, React e pytest.

## Global Constraints

- `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `LLM_API_STYLE`, `LLM_SUPPORTS_TOOLS` e timeout ficam no backend.
- Chat Completions é o estilo inicial de compatibilidade; o provider isola detalhes do SDK.
- Nenhum modelo recebe SQL, credenciais ou dumps completos do banco.
- A aplicação funciona quando IA está desabilitada ou indisponível.
- Tool de escrita exige ator autorizado, intent, confirmação e auditoria.
- MCP não possui repository nem SQL.
